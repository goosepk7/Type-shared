# WordEngine Effects

Pooled, phone-friendly VFX shared by both games, in two styles from one API:

- **Spectral** (Typing Wizards): glowing energy. Neon cores, ForceField shells, additive particles.
- **Solid** (Type to Defend): a stylized, real look. Real materials (Basalt, Glacier, Metal, Wood...), smoke, debris and lit particles.

The code is in `src/Shared/Effects/`. The palettes live in one place (`Palettes.luau`), the emitter presets in `Presets.luau` and the textures in `Assets.luau` (backed by `AssetIds.luau`, generated by `assets/textures/upload.py`). There is one renderer per kind (`Kinds/*.luau`).

Platform notes and sources are in `docs/platform/vfx.md`. Texture upload steps are in `docs/manual/vfx.md`.

## API

```lua
local Effects = WordEngine.Effects            -- require(ReplicatedStorage.WordEngine.Effects)

local h = Effects.play("projectile.meteor", { style = "Spectral", element = "Fire", to = hitPos, scale = 1.5 })
h:onFinished(function() ... end)              -- also h:stop(), h:isPlaying(), h:setTarget(model), h:pulse()

Effects.status(model, "Burn", 4)              -- refreshes (does not stack) the same status; at most 4 per target
Effects.clearStatus(model, "Burn")            -- or clearStatus(model) for all
Effects.reaction(Reactions.get("Fire", "Ice"), { at = cf })  -- or Effects.reaction("Steam", ...)
Effects.play(Reactions.material("wood", "Fire").vfx, { target = summonModel })

Effects.setDefaultStyle("Solid")              -- per game, once
Effects.setQuality("Auto" | "Ultra" | "High" | "Medium" | "Low")   -- settings menu
Effects.setShakeHandler(function(pos, intensity) ... end)          -- big explosions call this
Effects.serialize(id, params) / Effects.playSerialized(msg)        -- server -> client remote payloads
Effects.exists(id), Effects.ids(), Effects.stats(), Effects.clear()
```

### Params

| param | type | meaning |
|---|---|---|
| `style` | `"Spectral"` \| `"Solid"` | default `Effects.setDefaultStyle` (Spectral) |
| `element` | Element | picks the palette and the element-specific particles (default: the entry's element) |
| `at` | CFrame \| Vector3 | where (zones, bursts, explosions, walls) |
| `from`, `to` | Vector3 \| CFrame \| Instance | projectiles, beams, strikes, teleport |
| `target` | Instance (Model/BasePart) | followed by auras, shields, statuses, materials, spawn; homing for projectiles |
| `scale` | number | size multiplier (1 is about one character) |
| `colour` | `"#RRGGBB"` | overrides the palette (a 5-stop ramp is derived from it) |
| `duration` | seconds | looping effects run until `:stop()` unless this is given |
| `priority` | 0 / 1 / 2 | 0 ambient (dropped first), 1 normal, 2 local player (may overflow the budget by 25%, never distance-culled) |
| `seed` | number | deterministic randomness |
| `radius`, `length` | studs | zones, domes, walls |
| `points` / `targets` | {Vector3} / {Instance} | `beam.chain` hops |
| `impact` | effect id \| false | the projectile's impact on arrival (default `impact.<element>`) |
| `shake` | false | skip camera shake |
| `keepHidden` | bool | `spawn.dissolve`: leave the target hidden afterwards (default true) |

`Effects.play` never errors. Unknown ids fall back (`impact`, `status.stun`, `burst.nova` or `sparkle`) with one warning. The server gets an inert handle unless `Config.Visual.Effects.AllowServer` is set; play effects on clients. A handle from a culled or refused effect has the same API and simply finishes after `duration`.

## Budgets and quality

`Config.Visual.Effects.Budgets` sets the limits per tier. The starting tier comes from the device class (Desktop/Console High, Tablet/Phone Medium); the player's saved graphics level pulls it down (at most 3 gives Low) or up (9 or more gives Ultra).

| tier | effects | parts | emitters | beams | trails | lights | highlights | particle scale | detail | flipbooks |
|---|---|---|---|---|---|---|---|---|---|---|
| Ultra | 64 | 360 | 140 | 64 | 32 | 16 | 8 | 1.0 | 3 | yes |
| High | 48 | 260 | 100 | 48 | 24 | 10 | 6 | 0.85 | 3 | yes |
| Medium | 32 | 160 | 64 | 28 | 14 | 5 | 3 | 0.6 | 2 | yes |
| Low | 18 | 80 | 32 | 14 | 6 | 2 | 0 | 0.35 | 1 | no |

How the budget behaves:

- **Admission.** Each catalogue entry has a cost estimate (`Catalogue.cost(id)`). An effect that would exceed the tier is refused and gets an inert handle. Above 60% usage, particles thin smoothly down to 40%.
- **Optional extras.** Lights and highlights never block an effect; they are skipped when the tier is out of them.
- **Auto-degrade.** When the smoothed FPS stays below 40 for 2.5 s, the tier drops one step (3x faster below 24 FPS). After 12 s above 56 FPS it climbs back, never above the starting tier.
- **Culling and pooling.** Effects more than 450 studs from the camera are culled, except priority 2 and weather. Everything is pooled: parts, carriers, attachments, emitters (per preset), beams, trails, lights, decals and highlights. Emitters and trails stay in a cooling list until their last particle dies, then return to their pool.

## No z-fighting (enforced by tests)

- **Ground layers.** Discs and decals sit at `ground + DecalOffset * slot`, where the slot rotates through 1..24 globally. Overlapping layers from different effects therefore never share a plane.
- **Shells.** Concentric glow shells grow by at least `ShellRatio` (1.25).
- **Buried geometry.** Columns, walls and stems bury their bottom faces below the ground. Crossed or abutting parts use different lengths or radii, so no faces are coplanar.
- **Stacked copies.** When the same effect is started on the same spot (two players cast the same spell), each extra copy is scaled up by 7%, so their shells never coincide.
- **The test.** `tests/specs/effects.spec.luau` renders every id in both styles against real `@lune/roblox` instances. It samples every visible part 30 times over the first 4 s of each effect and fails on:
  - coplanar overlapping faces (Block faces, Cylinder caps, decal faces);
  - coincident spheres;
  - top faces on the ground plane.

  It also fails on any warning, error or pool/budget leak.

## Material reactions

`Reactions.material(materialIdOrRecord, element)` returns an outcome whose `vfx` is a `mat.*` id. The outcome table is in DESIGN.md section 7. Play it with `target = summonModel`; it follows the model and uses its bounding box.
